# Short Link Resolver Bot — V1

A Telegram bot that resolves ordinary HTTP/HTTPS redirect-based short links and returns the final destination URL.

## Supported
- Standard HTTP 301/302/303/307/308 redirects
- Immediate HTTP `Refresh` and HTML meta-refresh redirects (zero-second only)
- Clear detection of common waiting/interstitial pages that need JavaScript or manual verification
- Multiple redirect hops (up to the configured limit)
- URL validation and basic SSRF protections
- Optional Supabase logging
- Telegram webhook deployment on Koyeb or another ASGI host

## Not supported
This is a redirect resolver, not an ad-gate bypass service. It follows ordinary HTTP redirects and publicly exposed immediate (zero-second) HTML meta-refresh redirects. It does **not** execute JavaScript, click page buttons, defeat CAPTCHA, login walls, mandatory ad-view timers, paywalls, or other access controls. Timed refreshes are not followed. Some shorteners expose only an intermediate page; those are reported as unresolved rather than returning that page as a false final destination.

## Required environment variables
- `BOT_TOKEN`: Telegram bot token from BotFather
- `WEBHOOK_SECRET`: random secret used in the webhook URL and Telegram webhook header (use 32+ random characters)
- `PUBLIC_BASE_URL`: public HTTPS base URL of this service, e.g. `https://your-app.koyeb.app`
- `SUPABASE_URL`: optional Supabase project URL
- `SUPABASE_KEY`: optional Supabase service-role key (keep private; never commit it)
- `SUPABASE_TABLE`: optional log table name; defaults to `resolver_logs`
- `MAX_REDIRECTS`: optional; defaults to `10`
- `REQUEST_TIMEOUT`: optional seconds; defaults to `12`
- `MAX_REQUESTS_PER_MINUTE`: optional per-user in-memory limit; defaults to `20`

## Supabase table (optional)
```sql
create table if not exists public.resolver_logs (
  id bigint generated by default as identity primary key,
  telegram_user_id bigint,
  input_url text not null,
  final_url text,
  status text not null,
  error text,
  created_at timestamptz not null default now()
);
```
If Supabase variables are omitted, the bot runs without persistent logging.

## Deploy
1. Push this repository to GitHub.
2. Create a Koyeb Web Service from this repository.
3. Build command: `pip install -r requirements.txt`
4. Run command: `uvicorn app.main:app --host 0.0.0.0 --port 8000`
5. Add the required environment variables in Koyeb.
6. After deployment, set the Telegram webhook by opening:
   `https://YOUR-APP-DOMAIN/setup-webhook`
   This endpoint registers the webhook using `PUBLIC_BASE_URL` and `WEBHOOK_SECRET`.

## Local run
```bash
pip install -r requirements.txt
cp .env.example .env
uvicorn app.main:app --host 0.0.0.0 --port 8000
```
The application reads environment variables directly; load `.env` with your deployment platform or a dotenv runner if testing locally.

## Privacy and safety
- Never commit bot tokens, webhook secrets, or Supabase keys.
- Keep Supabase service-role keys server-side only.
- Resolver requests reject local/private network destinations and non-HTTP schemes.
- Logs may contain URLs submitted by users; disclose this in your bot's privacy notice if you enable logging.
